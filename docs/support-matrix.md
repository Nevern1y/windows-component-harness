# Support matrix

This matrix describes the checked-in implementation, not the aspirational architecture. `SUPPORTED` means the current CLI invokes the path through the production coordinator or restore service. `PARTIAL` means a bounded typed subset is implemented and the remainder is reported. `MANUAL` means observation or a user action is available but automatic mutation is intentionally absent. `LIBRARY ONLY` means a standalone adapter or library is implemented and fixture-tested but is not part of the current automatic CLI path. `UNSUPPORTED` is an explicit product boundary.

Status is intentionally conservative. A component can be discovered while its restore strategy is `PARTIAL`, `MANUAL`, `REAUTH_REQUIRED`, or `UNSUPPORTED`.

## Release and control surface

| Area | Status | Current behavior | Explicit boundary | Evidence |
|---|---|---|---|---|
| Windows 11 x64 CLI | **SUPPORTED** | `reforge.exe` exposes scan, inventory, package, target, plan, restore, resume, action, verify, report, and doctor commands. | The current target is `x86_64-pc-windows-msvc`; other platforms are not promised. | `crates/reforge-cli/src/main.rs`, `rust-toolchain.toml`, `crates/reforge-cli/tests/cli_smoke.rs` |
| Tauri desktop shell | **CLI ONLY** | The shell displays a CLI notice. `CLI_ONLY_BUILD` is hard-coded to `true`. | No Tauri invoke handler, native dialog plugin, filesystem plugin, or runtime switch is registered in this release. | `src-tauri/src/lib.rs`, `src-tauri/capabilities/main.json`, `ui/src/routes/CliOnlyNotice.svelte` |
| Local state and journal | **SUPPORTED** | Inventory/target JSON, object store, run state, reports, and SQLite journal are persisted under `%LOCALAPPDATA%\\Reforge` or an absolute `REFORGE_STATE_DIR`. | State is local application state and is not part of a portable package. | `crates/reforge-cli/src/main.rs`, `crates/reforge-restore/src/journal.rs` |

## Package and restore

| Area | Status | Current behavior | Explicit boundary | Evidence |
|---|---|---|---|---|
| Non-secret `.reforge` package creation | **SUPPORTED** | Canonical metadata, dependency graph, explicit selection, object index, source records, zstd frames, ZIP64 container, BLAKE3 IDs, bounded streaming, and atomic publication. | Existing destination files are rejected by the writer; selected secret content requires a vault. | `crates/reforge-package/src/{canonical,content_store,writer}.rs`, `crates/reforge-package/tests/{package,content_store,canonical,security}.rs` |
| Package inspection | **SUPPORTED** | Validates central directory, required entries, canonical documents, derived operations/sources, object hashes/lengths, archive bounds, and optional signatures without extraction. | Package metadata is untrusted until inspection and explicit plan/restore approval. | `crates/reforge-package/src/reader.rs`, `crates/reforge-package/tests/security.rs` |
| Optional package signatures | **PARTIAL / LIBRARY** | Ed25519 signature metadata and trust decisions are implemented and inspected by the package library. | CLI package creation currently passes no signature; a valid signature proves integrity/authorship only when its key is trusted out of band. | `crates/reforge-package/src/signature.rs`, `crates/reforge-package/tests/signature.rs`, `crates/reforge-cli/src/main.rs` |
| Age secret vault | **PARTIAL / LIBRARY** | The package library uses age v1 and zeroized buffers for the specified nested vault/recovery design. | The current CLI does not collect secure adapter values and rejects non-empty secret selection with `VAULT_REQUIRED`; no secret is copied to normal package bytes, logs, state, or reports. | `crates/reforge-package/src/vault.rs`, `crates/reforge-package/tests/vault.rs`, `crates/reforge-cli/src/main.rs` |
| Selection and dependency closure | **SUPPORTED** | Required dependencies are auto-added; optional dependencies and sensitive/large/manual/portable choices remain explicit warnings/policy decisions. | Recommendations are not authorization. A missing required dependency blocks package creation. | `crates/reforge-domain/src/selection.rs`, `crates/reforge-domain/tests/selection_policy.rs` |
| Rebuild and migration planning | **SUPPORTED typed path** | Compares package graph with target facts, topologically orders typed operations, records conflicts/manual actions, and gates trust/compatibility. | Migration never deletes target data. Target/policy decisions can block execution. | `crates/reforge-restore/src/{diff,compatibility,planner,operations}.rs`, `crates/reforge-restore/tests/{planner,conflicts,compatibility}.rs` |
| File/config restore | **SUPPORTED safe subset** | Writes tokenized user-scoped files atomically; merges JSON/JSONC/TOML with declared policies; backs up replaced files. | Protected roots, reparse paths, malformed content, secret literals, and unresolved conflicts are rejected or manual. | `crates/reforge-restore/src/handlers/{files,config}.rs`, `crates/reforge-restore/tests/{handlers_files,handlers_config}.rs` |
| User environment and PATH | **SUPPORTED safe subset** | Writes current-user non-secret values under HKCU\\Environment, merges PATH with validation/deduplication, broadcasts the setting change, and verifies. | System scope and secret-like values are not silently written. | `crates/reforge-restore/src/handlers/environment.rs`, `crates/reforge-restore/tests/handlers_environment.rs` |
| Provider/runtime installation | **PARTIAL** | Uses typed provider/runtime operations, built-in executable identities, bounded output, exact recorded source/version inputs, and verification descriptors. | No latest-version fallback, arbitrary package command, unreviewed bootstrap URL, or hidden installer/script execution. | `crates/reforge-restore/src/handlers/providers.rs`, `crates/reforge-discovery/src/providers/` |
| Browser/editor restore | **PARTIAL / MANUAL** | Typed browser artifact and VS Code extension handlers exist for explicitly constructed package operations. | Automatic source inventory is not wired into the current CLI scan; sessions/cookies/logins remain reauthentication/manual. | `crates/reforge-restore/src/handlers/{browsers,vscode}.rs` |
| Windows system registrations | **MANUAL** | Discovery and verification evidence can describe services, tasks, features, startup, shortcuts, and associations. | No arbitrary automatic registration mutation; default-app `UserChoice` hashes are never guessed or written. | `crates/reforge-discovery/src/providers/windows_registration.rs`, `crates/reforge-restore/src/handlers/manual_actions.rs` |
| Manual actions and reboot | **SUPPORTED** | Actions are durable, monotonic, redacted, acknowledgeable, and resumable. Reboot operations pause and require an explicit later `resume RUN_ID`. | MVP does not create hidden RunOnce or Task Scheduler persistence. | `crates/reforge-restore/src/{manual_actions,journal,executor}.rs`, `crates/reforge-restore/tests/{manual_actions,executor}.rs` |
| Verification and reports | **SUPPORTED** | Every selected component is reported, operation failures win over matching observations, statuses/counts/evidence/warnings/manual actions are redacted and persisted. | `verified` never means “everything cloned”; partial, unsupported, reauth, and failed states remain visible. | `crates/reforge-restore/src/verification.rs`, `crates/reforge-cli/src/report.rs`, `crates/reforge-restore/tests/security.rs` |
| Full machine clone/direct PC transfer | **UNSUPPORTED** | Not modeled as a package or operation. | Hardware, SID/ACL identity, drivers, hostnames, licenses, DPAPI, credentials, and machine-bound state are outside the portable user-environment contract. | `REFORGE_IMPLEMENTATION_SPEC.md` sections 0, 31, and 38 |

## Production registration note

The production CLI coordinator currently registers WinGet, Chocolatey, Scoop, Python, Rust, Go, .NET, PowerShell, npm/pnpm/Yarn/Bun, Windows registration, Codex/Claude Code/OpenCode, WSL, Docker, and generic executable adapters. It does not register the standalone browser or VS Code discovery adapters. That distinction is intentional in this matrix and must be revisited before claiming automatic browser/editor inventory in a release.

## Evidence and maintenance

The source URLs behind these boundaries are copied into [`docs/sources.md`](sources.md) and the canonical Section 39 source index in [`REFORGE_IMPLEMENTATION_SPEC.md`](../REFORGE_IMPLEMENTATION_SPEC.md). When an external behavior changes, update the adapter fixture, source ledger, and this matrix together; if evidence is insufficient, use `UNVERIFIED` and downgrade the behavior to manual rather than guessing.
